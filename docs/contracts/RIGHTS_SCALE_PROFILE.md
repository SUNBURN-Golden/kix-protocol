# 확장 권리 프로파일 — 계약 0.1 (초안)

문서 버전 0.1 · 작성 2026-10-08 · 상태: **초안. 미검토. 미측정.**

이 문서는 [권리 확장 청사진 v1](../blueprints/rights-scale-v1/README.md)의 §1–§8·§10과 RS-0 항목을 확장 프로파일의 계약으로 옮긴다. 채택 근거와 아직 고르지 않은 항목은 [RS-0 결정 기록](../decisions/RIGHTS_SCALE_RS0_DECISION_20261008.md)에 있다. 청사진은 역사적 제안으로 그대로 둔다.

이 버전은 구현, 배포, 운영 활성화, 측정 결과가 아니다. Astra 아키텍처 검토와 사용자 병합 전에는 확정이 아니다. 구조가 경합을 줄인다는 주장을 하지 않는다. 쓰기 집합이 페이지·샤드와 `cancel_show`로 나뉜다는 것은 구조 서술이다.

## 1. 기준과 비주장

**관측 기준.**

- 작업 시작 시 `git fetch origin main` 뒤의 `origin/main`과 작업 HEAD: `7481b0e16ce9b903abbffa62249bb91cd9e63cfe`. 스냅샷이며 이후 main의 영구 식별자가 아니다.
- 잠금 blob은 작업 전 요구값과 일치했다. `runtime/crates/kix-kernel/src/lib.rs`는 `69564b166f0c27f9af5d8422f0a466b18d74c20f`. `runtime/crates/kix-kernel/tests/quarantine_capacity.rs`는 `b607996c83a119c349f1cc90469ac1ba82764e20`. 이 노드는 두 파일을 수정하지 않는다.
- Sui framework rev는 `reference/v0.3-rc1/sui/Move.toml`에서 다시 읽었다. `808640d9b49aecf29d8e6f46033c15eca236efa7`. 이 노드는 pin을 바꾸지 않는다. 청사진 §3.1·§11의 프로토콜 한도와 그 blob ID는 그 문서가 기록한 값을 인용한다. 이번 세션은 그 외부 blob을 다시 해시하지 않았다.
- 16슬롯 참조 프로파일은 회귀 기준으로 보존한다. `reference/v0.3-rc1/**`는 수정하지 않는다. `rights_tests.move`의 `#[test` 접두 일치는 20이고, 그 중 1개는 `#[test_only]`, 19개는 테스트 함수다. 이 노드가 그 시험을 고치지 않는다. ZK 회귀도 고치지 않는다.
- 아무것도 측정하지 않았다. 아래 정수는 청사진 부록의 산술이지 처리량·가스·지연이 아니다.

**비주장.** 운영 준비, 내구성, 체인 확정, 법적 적합성, 익명성, TPS, p99, 출시 수용량을 주장하지 않는다. 시험 규모 16·1,024·16,384·65,536은 청사진 §7.1의 제안이며 달성값이 아니다. coin/TIX 모듈, 실자금, 실 PG·은행·KYC, 공개 엔드포인트, Sui testnet·mainnet, R2, 자체 복제·합의·저장 엔진, 커널 v5는 이 계약의 범위가 아니다.

## 2. 프로파일 정체와 공존

| 프로파일 | 정체 | 이 계약에서의 규칙 |
|---|---|---|
| 16슬롯 참조 프로파일 | `reference/v0.3-rc1/sui`의 `kix::rights`, 회로 깊이 4 산출물, 그 클라이언트와 시험 | 수정하지 않는다. 파일·시험·역사 문서의 "16개 슬롯" 문장을 확장된 것처럼 고치지 않는다 |
| 확장 프로파일 | 새 패키지, 새 회로, manifest 스키마 v2, 도메인에 들어가는 `profile_version`과 회로 manifest 해시 | 경로와 모듈 이름의 최종 값은 RS-1·RS-2가 고른다. 이 계약은 그 경로가 `reference/v0.3-rc1/**` 밖일 것만 요구한다 |

문서 버전 0.1과 온체인 `profile_version`은 다른 값이다. RS-1이 패키지에 넣을 상수는 참조 프로파일과 구분되어야 한다. 참조 프로파일의 domain은 show id이며 `profile_version`을 넣지 않는다. 확장 프로파일의 domain은 show id, `profile_version`, 회로 manifest 해시를 묶는다. 두 프로파일의 증명은 서로 재사용할 수 없다.

Wave 2가 `rights`를 제자리에서 확장한 기록이 있다. 이번 변경은 16 가정 자체이므로 제자리 수정이 아니라 새 패키지로 둔다. 새 패키지는 coin/TIX 모듈이 아니다. 프로그램 결정 §2.1의 `rights`·`zk_gate` 확장으로 읽는 해석은 결정 기록의 Astra 조건 (a)~(e)를 따른다.

진행 중인 참조 프로파일 공연은 생성 때 고정한 verifier를 끝까지 쓴다. 새 공연만 확장 프로파일을 고를 수 있다.

## 3. 객체 모델

로드맵 R-2가 수락한 구조는 독립 객체 분할이다. 아래 표가 확장 프로파일의 객체다. 16슬롯 프로파일의 함수 서명은 청사진 §3.6에 있으므로 여기에 다시 적지 않는다.

`IssuerCap`은 이 표의 확정 행이 아니다. 현행 발행자 서명 함수가 소유 객체를 참조로 받는 사실은 연산 표에 임시 입력으로만 적는다. 처리 방식은 §13에서 열린 채로 둔다.

| 객체 | 공유·소유 | 쓰는 연산 | 읽는 연산 |
|---|---|---|---|
| `ShowControl` | 공유. 읽기 위주 | 생성 단계의 페이지 claim. `cancel_show` | 모든 소비 함수. 읽기 전용이며 생략할 수 없다 |
| `InventoryPage` | 공유. ID는 `derived_object::claim(ShowControl의 UID, 페이지 번호)` | 그 범위의 `issue`, `attest_issuance`, `issue_paid`, `cancel_issuance`, `refund`, `revoke`, 위임 시작·종료 | 이전, 검표 허가, 현재성 확인, `accept_sale`, `attest_payment`, `shield` |
| GA 슬롯 범위 샤드 | 공유. `InventoryPage`의 GA 모드. 구매자가 슬롯을 고르지 않는 익명 슬롯 | 그 범위의 발행·환불 | 같은 범위의 현재성 확인 |
| `PaymentRefShard` | 공유. 결제 참조 바이트에서 결정적으로 라우팅 | `attest_issuance`, `attest_payment`, `cancel_issuance` | `issue_paid` |
| `NullifierShard` | 공유. nullifier 해시로만 라우팅. 슬롯·구획은 라우팅 입력이 아니다 | `consume_private` | 없음 |
| `ChallengeShard` | 공유. challenge 바이트의 해시로만 라우팅. 초안 이름이며 RS-2가 모듈 이름을 맞출 수 있다 | `consume_private` | 없음 |
| 노트 트리 | 공유. 공연당 하나. append-only | `shield` | `consume_private` (루트 비교) |
| 폐기 트리 | 공유. 공연당 루트 하나. 체인은 루트만 저장한다 | `revoke` | `consume_private` (현재 루트 비교) |
| `GrantControl` | 공유. grant마다 하나 | 회수 | 위임된 페이지의 소비·해제 경로. 읽기 전용 |
| `Ticket` | 공유 | 이전, 허가, 검표, 환불, 폐기, `shield` | 그 함수들 |

`ShowControl`이 담는 필드: show id, 발행자, `profile_version`, `open`, `cancel_generation`, verifier ID, domain, 게이트 목록, 결제확인자 목록, 불변 범위표(페이지 크기, 페이지 개수, 각 페이지의 반개구간, GA 범위). 페이지 ID 목록은 담지 않는다. 65,536개 ID는 객체 크기 한도를 넘긴다는 산술은 청사진 §3.5에 있다.

노트 트리, 폐기 루트, 샤드 객체의 ID도 목록으로 저장하지 않는다. `derived_object`로 `ShowControl` UID와 고정 키에서 계산한다. 페이지 키의 공간은 페이지 번호다. 트리·샤드 키는 그 번호와 충돌하지 않는 다른 키 공간이다. RS-1이 Move 타입을 고르되 이 충돌 금지를 지킨다. 이 계약은 키의 정수 상수를 정하지 않는다.

샤드 개수 S와 라우팅 해시의 구체 알고리즘은 운영 기본값 없이 RS-1의 시험 행렬에서 고른다. 계약이 고정하는 것은 다음뿐이다. 같은 바이트열은 항상 같은 샤드에 들어가고, 샤드 안의 존재 검사는 공연 전체의 존재 검사와 같다. nullifier 라우팅의 입력은 nullifier 해시뿐이고, challenge 라우팅의 입력은 challenge 바이트의 해시뿐이다.

연산별 읽기·쓰기·소유 입력은 아래와 같다. 모든 트랜잭션은 가스 코인도 쓴다. 소유 입력 열의 `IssuerCap`은 현행 서명을 임시로 적은 것이며 §13의 결정을 대체하지 않는다. 위임 중인 페이지에서는 §10이 `GrantControl` 읽기를 이 집합에 더한다.

| 연산 | 쓰기 | 읽기 | 소유 입력 (임시 열 포함) |
|---|---|---|---|
| `issue` | 페이지, 새 `Ticket` | `ShowControl` | `IssuerCap` 참조 |
| `attest_issuance` | 페이지, `PaymentRefShard`, 새 `IssuancePayment` | `ShowControl` | 없음 |
| `issue_paid` | 페이지, 새 `Ticket` | `ShowControl`, `PaymentRefShard` | `IssuerCap` 참조, `IssuancePayment` 값 |
| `cancel_issuance` | 페이지, `PaymentRefShard` | `ShowControl` | `IssuerCap` 참조, `IssuancePayment` 값 |
| `offer`, `accept_gift`, `authorize_admission`, `consume` | `Ticket` | `ShowControl`, 페이지, `Clock` | 없음 |
| `attest_payment` | `PaymentRefShard`, 새 `PaymentEvidence` | `ShowControl`, `Ticket`, 페이지, `Clock` | 없음 |
| `accept_sale` | `Ticket` | `ShowControl`, 페이지, `Clock` | `PaymentEvidence` 값 |
| `refund` | 페이지, `Ticket` | `ShowControl`, `Clock` | 없음 |
| `revoke` | 페이지, `Ticket`, 폐기 루트 | `ShowControl` | `IssuerCap` 참조 |
| `cancel_show` | `ShowControl` | 없음 | `IssuerCap` 참조 |
| `shield` | 노트 트리, `Ticket` | `ShowControl`, 페이지, `Verifier`, `Clock` | 없음 |
| `consume_private` | `NullifierShard`, `ChallengeShard` | `ShowControl`, 노트 트리, 폐기 루트, `Verifier`, `Clock` | 없음. 발신자는 게이트 |

`Verifier`는 공연 생성 때 한 번 고정하고 이후 바꾸는 함수가 없다. `Clock`은 프레임워크 시간 객체다.

## 4. 여섯 상한

페이지 크기나 회로 깊이를 공연 정원으로 읽지 않는다. 값의 상태 어휘는 결정 기록과 같다.

| # | 상한 | 값의 결정 방법 | 결정 주체 | 상태 |
|---|---|---|---|---|
| 1 | 공연 전체 정원 | 생성 때 확정하는 페이지 범위와 GA 범위의 합. 범위표는 봉인 뒤 불변. 봉인 뒤 페이지 추가는 0.1의 연산이 아니다 | 범위표 규칙은 이 계약. 봉인 뒤 추가 요구가 있는지는 Astra | 규칙 채택(초안). 봉인 뒤 추가는 OPEN |
| 2 | 저장 페이지·샤드 용량 P | L1 측정 전에 기본값을 두지 않는다. RS-1은 기본값 없는 시험 행렬을 쓴다. 청사진의 1·64·256·1,024와 상한 예 4,096은 예시이며 선택이 아니다 | Astra. 측정은 RS-4 L1 | UNDETERMINED |
| 3 | 동시에 유효한 권리 수 | 정원 이하. 환불과 예약 폐기가 재고를 되돌리는 참조 프로파일의 규칙은 유지한다. 폐기(`revoke`)는 재고를 다시 열지 않는다 | 이 계약 | 규칙 채택(초안). 별도의 숫자 상한 없음 |
| 4 | 누적 발행·재발행 이력 | 세대와 페이지별 발행 카운터는 u64. 결제 참조와 이력은 샤드와 이벤트로 둔다. 재발행 때문에 누적은 정원을 넘을 수 있다 | 이 계약 | 규칙 채택(초안) |
| 5 | ZK 노트·nullifier 보존량 | 노트 트리 잎 용량은 성공한 `shield` 횟수를 담는다. 공개 재발행은 노트를 추가하지 않는다. 루트 이력 길이 K는 manifest 필드다 | K의 운영 값은 DECISION_REQUIRED · Astra. 잎 용량 규칙은 이 계약 | 용량 규칙은 초안 채택. K는 UNDETERMINED |
| 6 | 단일 트랜잭션 처리 범위 | `MAX_BUNDLE_CHAIN`은 §6의 공식으로 유도한다. 숫자 상수는 실제 호출 형태가 정해지는 RS-1에서 고정한다. 이벤트만 보면 발급 512가 산술 천장이다 | RS-1 / Astra | 공식 채택(초안). 상수 UNDETERMINED |

상한 6은 잠금 커널의 `MAX_BUNDLE = 64`(좌석 묶음)와 별개다. GA 묶음에는 그 64가 없다. 커널 `MAX_SEATS = 4,096`도 별개이며 이 계약이 잠금 파일을 바꾸지 않는다.

## 5. 슬롯 정체와 인접성

- 슬롯 번호는 반개구간 `[0, 정원)`의 정수다.
- 각 `InventoryPage`는 범위표의 반개구간 `[start, end)` 하나를 소유한다. 구간은 서로 겹치지 않고, 지정석 구간들의 합은 지정석 정원과 같다. GA 구간도 서로 겹치지 않는다.
- 번호 `i`와 `i+1`은 묶음 목적에서 인접하다. 페이지 경계를 넘는 묶음은 한 PTB에서 원자적으로 처리하거나 §6에 따라 거절한다. 부분 성공은 없다.
- 공연장의 구획·행·열을 슬롯 번호로 보내는 대응, 그리고 페이지 구간을 커널 `Inventory::Seats` 구간으로 보내는 대응은 이 계약이 정하지 않는다. 담당은 RS-3b / Astra.
- 체인 GA는 슬롯 범위다. 커널 GA는 수량 카운터다. 실행자가 빈 슬롯을 고르는 방법과 카운터 대응은 RS-3b / Astra가 정한다. 0.1은 그 알고리즘을 만들지 않는다.

## 6. `MAX_BUNDLE_CHAIN` 유도

청사진 §3.1이 기록한 protocol 136 스냅샷 한도(blob `a45b246082453cb739e51bb0577bed646e4d1935`, 이번 세션 미재확인)를 입력으로 쓴다.

| 한도 | 기록된 값 | 묶음에 대한 의미 |
|---|---|---|
| `max_programmable_tx_commands` | 1024 | PTB 명령 수 |
| `max_input_objects` | 2048 | 입력 객체 수 |
| `max_arguments` | 512 | 명령 하나의 인자 수 |
| `max_num_event_emit` | 1024 | 발급 하나당 이벤트 2개이면 발급 수 ≤ 512 |
| `max_tx_size_bytes` | 131072 | 트랜잭션 크기 |
| `max_size_written_objects` | 5000000 | 쓰는 객체 총 크기 |
| `max_serialized_tx_effects_size_bytes` | 524288 | effects 크기 |
| `max_num_new_move_object_ids` | 2048 | 새 객체 수. 생성 단계화에도 쓴다 |
| `max_move_object_size` | 256000 | 객체 하나. 묶음 상수와는 별도로 페이지 크기를 구속 |

`MAX_BUNDLE_CHAIN`은 위 한도를 실제 호출의 명령 수, 입력 객체 수, 인자 수, 이벤트 수, 트랜잭션 크기, 쓰기 크기, effects 크기에 대입했을 때의 최소 발급 수다. 이벤트 항만 적용하면 천장은 512 발급이다. 그 천장을 상수로 확정하지 않는다. 실제 호출이 이벤트를 더 쓰거나 객체를 더 만지면 상수는 512보다 작아진다. RS-1이 호출 형태를 고정한 뒤 상수를 패키지에 둔다.

초과는 전용 오류로 거절한다. 0.1은 prepare와 finalize로 나뉜 별도 계약을 두지 않는다. 나중에 그 계약이 필요하면 두 PTB는 원자가 아니며, 사이에 예약이 남고, 만료·해제 경로가 있어야 하며, 중간 상태를 정상 거래로 표시하지 않는다.

시험은 한도−1에서 성공, 한도에서 성공, 한도+1에서 거절이다. 상수 확정 전의 시험은 공식을 인코딩한 값으로 돌리고, 그 값이 운영 상수가 아님을 표시한다.

## 7. 생성 단계화와 봉인

- 봉인 전에는 `open`이 거짓이다. 봉인 전 소비는 모두 거절된다.
- 페이지 ID는 `derive_address(ShowControl ID, 페이지 번호)`로 계산한다. 같은 부모·키의 두 번째 claim은 중단된다. 생성 트랜잭션의 응답이 유실된 뒤 같은 키로 다시 claim하면 두 번째가 중단되므로 권위가 둘이 되지 않는다.
- 공유 객체는 만들어진 그 트랜잭션에서만 공유할 수 있다. claim, 생성, 공유는 한 트랜잭션이다. claim은 부모를 가변으로 받으므로 생성 단계에서만 `ShowControl`을 쓴다. 파생 객체는 부모의 자식이 아니므로 이후 페이지 접근은 부모 쓰기가 아니다. 근거 문장은 청사진 §3.1·§3.5가 인용한 고정 rev 문서다.
- `max_num_new_move_object_ids`가 2048이므로, 새 ID가 페이지당 1개일 때 P=1·65,536슬롯은 최소 32번의 생성 트랜잭션이고 16,384슬롯은 8번이다. 청사진 부록의 산술이다. 페이지마다 `Claimed` 동적 필드가 ID를 하나 더 쓰면 트랜잭션당 페이지 수는 줄어든다. 계수는 미확인이며 RS-1이 센다. 이 계약은 계수를 정하지 않는다.
- 봉인은 범위표의 페이지가 모두 claim·공유된 뒤에만 `open`을 참으로 만든다. 그때 verifier와 범위표는 이후 함수가 바꾸지 못한다.
- 성공한 `cancel_show`는 `open`을 거짓으로 하고 `cancel_generation`을 1로 둔다. 이미 닫힌 공연의 다시 닫기는 거절된다. 소비 거절의 기준은 `open`이다. 범위표는 취소로 바뀌지 않는다.
- 봉인 뒤 페이지 추가는 0.1에 없다. 범위표 불변이 이 버전의 전제다. 그 요구가 있는지는 OPEN이며 주체는 Astra다.

## 10. 위임 경계

모델 1은 승인되어 있다. grant와 비협조 회수는 미구현이고 위임 실행은 비활성이다. 이 절은 RS-3a·RS-3b가 쓸 초안이며, 그 구현을 이 노드가 하지 않는다. 회수 cut은 온체인 grant 무효화와 페이지 소비 차단으로 한정한다. 커널의 종결·회수·해제·색인·GC는 범위가 아니다.

1. 한 슬롯의 원권위는 그 슬롯을 소유한 페이지 하나다.
2. 위임의 최소 단위는 페이지 또는 GA 샤드다. 페이지 안의 일부 슬롯만 위임하지 않는다. P가 그 단위의 크기다. P는 §4에서 UNDETERMINED다. 운영상 충분한지는 측정 전이다.
3. 위임된 페이지는 `delegated_to`에 grant ID를 둔다. 위임 중 `issue`, `attest_issuance`, `issue_paid`, `cancel_issuance`, `refund`는 `GrantControl`을 읽기 전용으로 확인한 경로만 허용되고, 온체인 직접 호출은 거절된다. `refund`와 `cancel_issuance`를 포함한다.
4. grant의 현재성은 `GrantControl` 한 곳에 둔다. 페이지는 grant ID만 가리킨다. 신규 약정 차단 cut은 `GrantControl`에 대한 한 번의 쓰기다. 페이지별 `delegated_to` 해제는 그 뒤 검증된 미사용 잔량을 회수하는 단계이며 페이지마다 별도 쓰기다.
5. 회수 순서는 모델 1의 A-4(`docs/decisions/AUTHORITY_MODEL_1.md`)와 LC-CUT(`docs/contracts/STATE_LIFECYCLE.md` §4)를 청사진 §6이 제안한 순서로 구성하는 초안이다. 그 두 문서에는 이 다섯 단계가 순서대로 적혀 있지 않다. 회수 의사 기록, 신규 약정 차단 cut, 체인 경계 확정, cut 이전의 미발행 약정·늦은 capture·반환 의무 보존, 검증된 미사용 잔량만 회수. 시간 경과만으로 전량 회수하지 않는다. cut을 증명하지 못하면 해당 페이지의 새 소비와 재위임을 보류한다.
6. 응답 유실·timeout·NotFound는 미실행이 아니다. 새 거래를 만들지 않고 같은 서명 바이트로 조회·대사한다. 재전송은 현재 실행 허가와 fence가 확인된 경우의 같은 바이트로만 한다. 이것은 R2 fence의 구현이 아니다.
7. 페이지 하나를 커널 인벤토리 하나에 대응시킬 수 있는지는 RS-3b가 확인한다. 이 계약은 대응이 가능하다고 하지 않는다. 4,096석을 넘는 지정석이나 64를 넘는 좌석 묶음의 위임 실행은 잠금 파일을 그대로 둔 새 crate이며 Track K v5의 별도 승인 뒤다.

## 11. 이전과 공존

진행 중인 16슬롯 공연을 확장 프로파일로 옮기는 경로는 두지 않는다. 청사진 열린 질문 6에 대한 0.1의 답이다. 공연은 생성 때 프로파일을 고르고, verifier는 그때 고정된다. 참조 프로파일의 Move 시험 19개와 ZK 회귀는 그 프로파일의 회귀로 남는다. 확장 프로파일의 결과를 그 회귀의 성공에 합산하지 않는다.

## 12. 영향 처리

## 13. 열린 항목, 미정 항목, 비주장

**`IssuerCap`은 OPEN이다.** 결정 시점은 `rs-1-issuercap-probe`가 끝난 뒤다. 그 프로브는 RS-1 다음의 별도 노드다. 선택지는 세 가지이며 0.1의 채택 값은 비어 있다.

1. cap을 페이지 또는 grant별로 나눈다.
2. 소유 객체를 쓰지 않는 권한 확인으로 바꾼다.
3. 한 cap이 만드는 처리량 천장을 수용한다.

결정 기준: 같은 `IssuerCap`을 참조로 쓰는 발행자 서명 트랜잭션 두 건을 localnet에서 동시에 보냈을 때 직렬화되는지. 프로브의 원시 출력 뒤에 Astra가 고른다. 그 전까지 연산 표의 소유 입력 열은 임시 기록이다. cap을 나눈 구성의 RS-C01 시험은 그 선택을 한 뒤에만 열린다.

청사진 RS-1 인수 조건은 이 프로브를 RS-1 안에 적는다. 로드맵과 노드 정의는 `rs-1-issuercap-probe`로 분리한다. 0.1은 로드맵의 분리 노드를 따른다. 불일치는 결정 기록의 범주 B다.

| 항목 | 상태 | 주인 |
|---|---|---|
| `IssuerCap` 처리 | OPEN. `rs-1-issuercap-probe` 전까지 선택 없음 | 프로브 뒤 Astra |
| 페이지 크기 P | UNDETERMINED. 기본값 없는 시험 행렬 | Astra. 측정은 RS-4 L1 |
| 샤드 개수 S와 라우팅 해시 알고리즘 | UNDETERMINED. 유일성 술어만 고정 | RS-1이 시험 행렬. 운영 값은 Astra |
| 노트 루트 이력 K | UNDETERMINED. manifest 필드 | DECISION_REQUIRED · Astra |
| 0이 아닌 폐기 창 | 제품 정책. W=0만 초안 채택 | DECISION_REQUIRED · Astra |
| 공개 트리 보존 기간 | UNDETERMINED | DECISION_REQUIRED · Astra (정책 값인 경우) |
| `MAX_BUNDLE_CHAIN` 숫자 상수 | 공식만 채택. 이벤트 산술 천장 512는 상수가 아니다 | RS-1 / Astra |
| 봉인 뒤 페이지 추가 | OPEN. 0.1 범위표는 불변 | Astra |
| 구획·행·열과 슬롯 번호의 대응 | OPEN | RS-3b / Astra |
| 페이지와 커널 구간의 대응 | OPEN | RS-3b / Astra |
| 온체인 GA의 빈 슬롯 선택과 커널 카운터 대응 | OPEN. GA 범위 객체 자체는 §3에 포함 | RS-3b / Astra |
| `Claimed` 동적 필드가 더하는 새 ID 계수 | 미확인 | RS-1이 측정 |
| `shield` 경합의 완화 연산 | OPEN. 새 명령 없음 | 측정은 RS-4. 새 명령은 DECISION_REQUIRED · Astra |
| 폐기 저장 (b)의 충돌이 클 때의 대체 | OPEN. 임계 숫자 없음 | RS-4 보고 뒤 Astra |

**비주장 (반복).** 이 초안은 검토 전이고 측정 전이다. ③이 부모 경합을 없앤다고 하지 않는다. `ShowControl`의 취소 쓰기는 진행 중인 모든 소비와 순서화된다. 그 비용은 측정 대상이다. 참조(`&`)로만 쓰는 소유 객체가 잠기는지는 확인되지 않았다. Poseidon·증명·검증의 가스 환산, 깊이별 제약 수, 인덱서 신뢰는 미확인이다. 고정 스냅샷 한도는 현재 네트워크의 값이라고 하지 않는다.
