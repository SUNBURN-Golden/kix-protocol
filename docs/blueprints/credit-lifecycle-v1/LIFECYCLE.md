# 여신 수명·사건 계약 후보

CR-LIFECYCLE-CANDIDATE · 설계 전용. 기존 F04 FSM을 대체하지 않는다. 아래 상태명·명령은 wire/API에 아직 없다.

## 1. 서로 독립인 상태 축

| 축 | 후보 상태 | 금지하는 해석 |
|---|---|---|
| 약정 | PROPOSED / ACCEPTED / ACTIVE / SUSPENDED / EXPIRED / CLOSED | 만료·중단은 기존 채무 소멸 아님 |
| 인출 지급 | REQUESTED / RESERVED / SUBMITTED / UNKNOWN / CONFIRMED / FAILED / RETURNED | provider 접수는 수취 완료 아님 |
| 상환 입금 | UNVERIFIED / VERIFIED / SUSPENSE / ALLOCATED / REVERSED | 입금 수신만으로 원금 감소 금지 |
| 채무 이행 | NOT_DUE / CURRENT / PAST_DUE / RESTRUCTURED / SATISFIED | 연체는 자동 담보 처분 권한 아님 |
| 회수 case | OPEN / DISPUTED / ARRANGEMENT / RECOVERY / CLOSED | case 종료와 채무 소멸 분리 |
| 회계 표시 | NORMAL / IMPAIRED / CHARGED_OFF 등 후보 | 회계 분류 미정; 상각은 면책 아님 |

UNKNOWN은 지급의 관측 불확실성이다. 차주의 연체 상태와 혼합하지 않는다. 후보 RETURNED는 기존 지급 확정을 덮어쓰지 않고 후속 반환 사건을 연결한 현재 표시다.

## 2. 인출 상태 전이와 명령 경계

| 입력/사건 | 허용 조건 | 기록·한도 효과 |
|---|---|---|
| 요청 | 인증 actor, 같은 자산, 활성 약정, 유효 동의·심사·적격성 | stable command ID와 payload 결합 |
| 예약 수락 | 모든 한도·claim slice·재원 예약의 원자성 | RESERVED; 첫 결과·예약·outbox 함께 보존 |
| 제공자 제출 | 현재 실행 권한·검증 계좌·원 provider 결합 | SUBMITTED; transfer intent/attempt 기록 |
| 응답 유실/불확실 | 전송/처리 여부를 입증 못함 | UNKNOWN; 예약 유지; 새 송금 금지 |
| 확정 지급 관측 | 제공자 계약에 맞는 인증 사실·금액·자산·수취인 결합 | CONFIRMED; 예약→확정 노출 단일 전환 |
| 지급 전 실패 확정 | 실행되지 않았다는 계약상 충분한 증거 | FAILED; 그 증거에 의해 예약 해제 |
| 제출 전 취소 | outbox 미전송을 원자적으로 증명 | 취소 결과 보존·예약 해제 |
| 지급 후 반환 관측 | 원 지급 참조, 실제 반환액·자산 검증 | 별도 사건; 부분 반환 가능, 채무 조정은 승인 정책 |

provider가 idempotency·확정 조회·미실행 증거를 제공하지 않는 범위는 자동 지급 복구 불가로 남긴다. timeout, 단일 not-found, 작업자 재시작, TTL 만료만으로 FAILED 처리하거나 예약을 풀지 않는다. stable operation ID는 routing epoch/정책 변경에도 보존한다. 동일 키·다른 payload는 거절한다.

약정 승인 취소나 계좌 변경이 송금 중 발생하면 원 송금의 수취 대상을 바꾸지 않는다. 새 계좌는 새 검증 revision을 거쳐 향후 별도 명령에만 적용한다. 조회 재생은 외부 송금 재실행 권한이 아니다.

## 3. 상환표·이자·비용의 결정론

정책에 원금 기준, 적용 금리의 정수 분자/분모, day-count 규칙, 시간대/영업 달력, 납기 이동, 유예 기간, 반올림 단위·시점, 비용 발생 조건, 중도상환, 연체 적용 및 변경 효력을 명시한다. 어느 하나라도 필요한 값이 미정이면 계산하지 않는다. 일률적인 금리·비용·상환기간 기본값을 만들지 않는다.

합성 단리 ACT/365F를 **선택한 fixture에 한해서** 구간 i의 이자 후보는 `P_i × rate_num × days_i / (rate_den × 365)`다. 잔액·금리가 바뀌면 구간을 나누고 유리수 또는 정확한 정수 잔여를 유지한다. 반올림을 구간마다 할지 청구 단위로 할지 정책에 고정한다. 이 예시는 운영 상품, 법적 APR, 복리·연체이자 규칙을 정하지 않는다.

동일 기간의 재계산은 같은 accrual identity로 중복 적용을 막는다. 소급 사실/오류가 생기면 과거 결과를 지우지 않고 correction과 대체 계산을 연결한다. 상환표는 최초 버전과 변경 버전을 보존하며 아직 도래하지 않은 예상 금액을 확정 채권으로 섞지 않는다.

## 4. 입금·배분·보존식

입금 검증 키는 provider/account/environment + 외부 거래 identity에 결합한다. 금액만 같다는 이유로 입금을 매칭하지 않는다. 중복 통지·부분 입금·다중 약정 일괄 입금·출처 불명·초과 입금·반환·정정을 구분한다.

이자/비용/원금/연체분 배분 순서와 다중 약정 간 순서는 승인된 상품 정책에 있다. UI나 요청 도착 순서로 정하지 않는다. 미정 순서는 SUSPENSE다. 고객 지급 지시의 적용 여부도 계약 입력이다. 정산금 자동 sweep은 명시된 권한·양도/상계·환불 우선 관계와 provider 계약이 갖춰질 때만 별도 경로로 허용한다.

자산별 합성 보존식:

`확인 입금 순액 = 채무 배분 누계 + 미배분 잔액 + 확인된 환급 순액`.

확인 입금 순액은 취소·반환된 수신을 반영한 금액이고, 배분 누계는 reversal을 반영한 순액이다. outbound 환급 의도/UNKNOWN은 아직 확인 환급으로 차감하지 않고 미배분 잔액 중 예약분으로 잡는다. 지급액을 취소한 사실과 고객 채무의 소멸은 별도 정책으로 연결한다.

`계약상 원금 잔액 = 확인 실행 원금 + 승인된 원금 조정 − 확정 원금 상환 − 유효한 채무 소멸 조정`.

부호 있는 조정은 근거·승인·revision이 필요하다. 이자·비용의 원금 편입은 기본 금지이며 명시 정책이 없으면 구현하지 않는다. 장부 상각은 위 식의 채무 소멸 조정에 넣지 않는다. 회계 장부 잔액과 계약상 채무 잔액은 각 별도 projection으로 대사한다.

## 5. 연체·조정·회수·종결

연체 계산은 유효 상환표, 기준일/시간대, grace 규칙, 배분된 확인 입금으로 한다. 후보 `days past due`는 해당 정책에서 미지급이 된 가장 이른 납기의 경과 일수다. 미도래 잔액·분쟁 금액을 어떻게 분류할지는 정책으로 구분하며 조회 지연만으로 추심 단계를 올리지 않는다.

연체 bucket 경계, 안내 빈도·채널·담당자, 조정/유예 권한, 기한이익 관련 처리, 담보/채권 집행은 미정 정책이다. 자동 법적 통지·추심·압류·담보 실행을 이번 설계 산출물로 가동하지 않는다. 제안→담당자 검토→승인된 실행→증거 수신의 경계를 설계하고 실제 메시지·외부 명령은 별도 권한을 요구한다.

채무 조정은 원 채권·약정·상환표를 보존하고 새 변경 계약/동의/발효일/상환표로 연결한다. DEFAULTED가 terminal인 F04 건을 수정하지 않고 새로운 servicing case에서 원 건을 참조하는 마이그레이션 ADR이 필요하다. 후기 입금은 폐쇄 case에서도 버리지 않고 새 사실/회수 사건으로 연결한다.

회수 성과는 실제 확인된 회수액과 비용을 자산별로 기록한다. 회수 예상액·회수채권·상각을 신규 대여 재원으로 넣지 않는다. 채무가 0이어도 unresolved transfer, suspense, 분쟁, 환불/반환 의무가 있으면 무조건 완전 종결하지 않는다. 약정 종료, 채무 이행 완료, case 운영 종결, 증거 보존을 따로 판정한다.

## 6. 보안·장애·export

신원 원문, 신용 자료, 수취계좌, 동의 증거는 별도 접근 scope와 검증 참조로 연결한다. 로그/브라우저 intent store에는 비밀정보를 넣지 않는다. 보존·삭제 충돌은 담당자 결정으로 남기고 사건 증거를 임의 GC하지 않는다.

시험 중단점은 한도 예약 commit 전후, outbox 송신 전후, provider 수락 후 응답 전, 관측 수신 후 적용 전, 입금 배분 commit 전후, 재평가와 draw 경쟁, 회수 입금의 역순 도착이다. 현재 writer fencing·첫 결과·중복 방지·UNKNOWN 보존을 검증한다. 금융 export는 원 source cut, 투영 watermark, 정책/상환표 revision, gap와 synthetic provenance를 포함한다. 복수 shard cursor 벡터만으로 전역 일관성을 주장하지 않는다.
