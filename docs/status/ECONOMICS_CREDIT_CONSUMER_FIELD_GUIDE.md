## Histories and consumer example

Each scenario uses a fresh session, separate order/group/advance IDs, public
capture confirmation and settlement. Both advances (`6000` and `4000`) are
offered the literal original `claim`, approved, bound, then drawn. The first
successful draw freezes the face; offer alone does not. Both advance views
used for aggregation are captured after both draws, at the same observation
point. The injected `_CapturedSettlementReader` exists only in the test module:
it holds detached public settlement envelopes captured before credit operations
and returns detached copies with identical content. It never accesses
`session._settlement`, changes provenance, derives a face, or mutates settlement.

| ID | Explicit history after draws | Distinction |
| --- | --- | --- |
| `P_partial_requester` | Refund only `line-1` (`6000`); distribute `['organizer-1', 'platform']`; observe mock acceptance `6000` | `REQUESTER`; payee faces unchanged; distribution applies `9700/300`; no recovery |
| `F_full_before_distribution` | Refund both lines once (`10000`, `CASH_REFUND_FIXTURE`); attempt distribution; observe mock acceptance `10000` | `FIXTURE_FULL_GROSS_RECLASS`; unpaid obligations cancelled `9700/300`; economics distribution refuses `GROUP_NOT_SETTLED` |
| `FD_full_after_distribution` | Distribute `9700/300`; refund both lines once with same full-refund route; observe mock acceptance `10000` | Distributions retained; recovery due `9700/300`; no unpaid cancellation |

No full history is constructed by summing successive partial refunds. A full
refund prepares/sends the existing mock REFUND intent; it is not a completed
provider return. The F refusal comes from the economics group phase guard,
not from `distribution_blocked` (which stays false). The unchanged direct
settlement behavior remains separately characterized by existing tests.

For a caller reading the vector JSON (standard JSON parsing only):

```python
scenario = vectors['scenarios'][0]  # P; not an external read endpoint

# Existing observation functions take F/C and A directly, with explicit inputs:
variance = observe_settlement_variance(F, C, tolerance=0)  # synthetic input
exposure = observe_shared_exposure('synthetic-pool-p', A, limit=10000)
# Both results stay NOT_BOUND, repair NONE, authorizes_exposure False.
```

## Exact field paths

For a live **in-memory reference session** only,
`G = session.view(order_id)['orders'][order_id]['groups'][group_id]`,
`S = G['settlement']`, `F = S['claim']`.
In vectors, each checkpoint is
`scenarios[i].steps[j].result.ok` where `step_id` is `frozen`, `after_refund`,
`after_distribute` or `after_accept`; its `group` is G, `credit.claim` is C and
`credit.views[k]` is A[k]. Ordinary operation results are complete `{ok: ...}`;
the F distribution error is `{error: {type, code}}`. `capture_confirm` records
the existing helper's complete return (capture submission); the helper also
confirms it through the public API before settlement. No private state is exported.

| Public producer / exact field | Meaning and limit |
| --- | --- |
| `G.phase` | Economics group `SETTLED`, `DISTRIBUTED` or `REFUNDED`; distinct from `S.phase` |
| `G.settlementId`, `G.tradeId` | Must match `S.settlement_id`/`F.claim_id` and `F.trade_id`; no legal-party binding |
| `G.refundReserved['leg-1']`, `G.refundedLines[]` | Reserved captured atoms and selected lines; not repayment or accepted return |
| `S.phase`, `S.settlement_id`, `S.claim` | FSM envelope; phase stays `COMMITTED` throughout these histories |
| `F.claim_id`, `F.trade_id`, `F.currency`, `F.gross` | Binding identities; `KRW`, `10000` fixture units |
| `F.obligations[*].payee`, `.face` | Sorted payee rows `organizer-1: 9700`, `platform: 300`; role labels only |
| `F.obligations[*].distributed` | Mock allocated amount; not a bank transfer |
| `F.obligations[*].cancelled_unpaid` | Cancelled unpaid obligation under full-gross reclassification |
| `F.obligations[*].outstanding` | `face - distributed - cancelled_unpaid`; sum feeds variance |
| `F.obligations[*].recovery_due`, `F.recovery_due` | Distributed recovery per payee and sum; no recovery execution |
| `F.confirmed_cash` | Synthetic confirmation `10000`, unchanged by distribution/refunds; not bank balance or credit funding |
| `F.refund_face`, `F.refund_accepted`, `F.refund_outstanding` | Bound refund, mock accepted cancellation, difference; no customer-credit confirmation |
| `F.refund_bearer_policy` | `NONE`, `REQUESTER` (P) or `FIXTURE_FULL_GROSS_RECLASS` (F/FD) |
| `F.fixture_reclassified`, `F.distribution_blocked` | Full-gross marker; blocked remains false in these public snapshots |
| `F.pg_adjustment_outstanding` | Equals mock `refund_accepted`; increases to `6000/10000` on acceptance. Not `refund_outstanding`, which becomes zero |
| `credit.view_claim(claim_id).open_face` | C: original frozen unpaid face `10000`, never recomputed here |
| `C.reserved_open`, `C.residual_unreserved` | `10000`, `0`; count once per claim, not once per advance |
| `C.confirmed_cash_on_face`, `C.recovery_due_on_face` | Frozen `10000`, `0`; no later recovery added to ceiling |
| `C.snapshot_frozen` | True after the first successful draw; C has no refund fields |
| `credit.view(advance_id).phase` | A[k]: `DRAWN`, with `note_status: NOTED` throughout |
| `A[k].drawn_exposure`, `.repaid_exposure`, `.outstanding_exposure` | `6000/0/6000` and `4000/0/4000`; mock exposure integers only |
| `A[k].exposure_ledger`, `.snapshot_frozen` | `MOCK_EXPOSURE`, true; same claim capacity in both views |
| `A[k].settlement_gate`, `.mock_settlement_commit_observed` | `MOCK_COMMIT_OBSERVED`, true; historical draw-time observation, no finality |
| `credit.export_journal()[*].body.face` (offer entries) | Literal F at offer, byte-equal under canonical serialization |
| Checkpoint `credit.journal`, `credit.state_digest` | Entire journal and public state digest; byte-stable across all economics-only actions, not durability or a signature |
| Checkpoint `variance.observable`, `.variance`, `.companion` | Current outstanding versus frozen face; cash/recovery diagnostic companions |
| Checkpoint `shared_exposure.observable`, `.claims[]` | Per-advance exposure totals and once-per-claim capacity |
| Both observer results: `mapping.contract_status`, `mapping.repair`, `refund_component` | `NOT_BOUND`, `NONE`, `NOT_BOUND` at every checkpoint |
| Both observer results: `fail_closed`, `mutates_state`, `authorizes_exposure` | true, false, false, even at tolerance/limit equality |

Amounts above are integers in the mock KRW unit. Nested commerce quote/proposal
`atoms` are decimal strings; copy complete public snapshots without coercing
those fields or treating their `executionAuthorized: false` as authority.

## Independently stated arithmetic

Original unpaid face is `9700 + 300 = 10000`. Credit reservations are
`6000 + 4000 = 10000`; exposure outstanding is drawn `10000` minus repaid `0`.
Every shared observation has **two advances, one claim**, open/reserved `10000`
and residual `0`. Summing claim capacity per advance would incorrectly double
it. The shared limit is explicitly synthetic `10000`, so `within_limit` is true
at equality and still authorizes nothing.

| Checkpoint | Settlement outstanding sum | Variance (`sum - 10000`) | Recovery delta | Refund face / accepted / adjustment |
| --- | ---: | ---: | ---: | --- |
| All `frozen` | 10000 | 0 | 0 | 0 / 0 / 0 |
| P `after_refund` | 10000 | 0 | 0 | 6000 / 0 / 0 |
| P `after_distribute` | 0 | -10000 | 0 | 6000 / 0 / 0 |
| P `after_accept` | 0 | -10000 | 0 | 6000 / 6000 / 6000 |
| F `after_refund`, `after_distribute` | 0 | -10000 | 0 | 10000 / 0 / 0 |
| F `after_accept` | 0 | -10000 | 0 | 10000 / 10000 / 10000 |
| FD `after_distribute` | 0 | -10000 | 0 | 0 / 0 / 0 |
| FD `after_refund` | 0 | -10000 | 10000 | 10000 / 0 / 0 |
| FD `after_accept` | 0 | -10000 | 10000 | 10000 / 10000 / 10000 |

Cash delta is `10000 - 10000 = 0` at every checkpoint. Recovery delta is
`F.recovery_due - C.recovery_due_on_face`; neither companion enters variance or
the tolerance gate. Tolerance `0` means only zero variance is within tolerance.
Acceptance changes only `refund_accepted`, `refund_outstanding` and
`pg_adjustment_outstanding` on F; it does not repay credit, release reservations,
revalue the frozen face, clear recovery or move bank money.
