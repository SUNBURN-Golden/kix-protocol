## 결정론과 버전 경계

[KIX Canonical Encoding v1](CANONICAL_ENCODING_V1.md)은 UTF-8·ASCII 객체 키 정렬·NFC 문자열·정수·큰 금액 문자열·입력 제한·해시 영역을 고정한다. Python과 TypeScript가 바이트·해시뿐 아니라 자산 ID와 견적·결제 배정·행 반환안을 독립적으로 계산해 비교한다.

- 기계 ID를 ASCII로 제한하고 largest-remainder 동률 해소에도 같은 규칙을 사용한다.
- 새 계산 스키마는 `kix:commerce:2`, 자산 ID는 `asset-v2-...`다. 원 S06 v1 결과를 자동으로 다시 해석하지 않는다.
- 기존 `common.digest`·장부·pending·receipt·복구·archive·paid Sui fixture의 해시는 그대로 둔다. 새 규격을 기존 파일에 일괄 덮어쓰지 않는다.
- Move·회로에 CE1을 이미 연결한 것으로 주장하지 않는다. 기존 체인·ZK 회귀는 기존 경로의 호환성을 검사한다.

## 자산 문맥을 유지하는 실행 입력

`execution_contracts.py`의 `AssetAmount`는 `assetId`와 정수 `atoms`에 명시적으로 선택된 `RegistryContext`를 결합한다. JSON에서는 atoms를 십진 문자열로 운반한다. 계산용 `Amount`를 넘길 때도 전체 AssetSpec이 선택된 문맥에 등록돼 있어야 한다.

`RegistryContext`는 양수 버전, 출처, 대상 영역, 전체 자산 명세 집합을 불변 값으로 고정한다. **현재는 신뢰하는 호출자가 선택한 시험 설정**이며, 실제 서명·등록 권한을 인증하는 서비스는 아니다. 외부 요청이 주장하는 레지스트리를 스스로 승인된 것으로 받아들이면 안 된다.

간략한 `{assetId, atoms}`만으로는 레지스트리 개정판을 식별할 수 없다. 저장·전달에는 `AssetAmount.to_record()`가 생성하는 스키마 버전·레지스트리 버전·문맥 해시·출처·영역·전체 자산 명세·금액을 함께 사용한다. `from_record()`는 별도로 선택한 문맥과 대조하며, 버전 번호만 같은 다른 자산 집합이나 정밀도를 묵시적으로 채택하지 않는다.

`registryHash`는 `digest('kix:asset-registry-context:1', RegistryContext.to_dict())`다. 자산 집합을 ID 순으로 정렬하므로 같은 집합의 입력 순서 변경은 허용하고, 같은 버전·출처·영역 아래 자산 추가·제거·명세 변경은 거절한다. 이 해시는 선택된 설정과의 일치를 확인할 뿐 외부 등록 권한의 인증을 대신하지 않는다.

이 계약은 데이터를 검증하는 경계다. 견적·환불안을 결제 관측, 실제 자금 이동, 지급 허가로 만들지 않는다. 승인된 정책·자산 레지스트리의 영속 운영과 서명·권한 확인은 S07 주문 생성 시 함께 구현한다.

## 의미가 다른 정수형

모든 새 정수형은 서로 다른 런타임 타입이다. bool·float·다른 정수형 객체·음수·범위 초과를 거절한다. wire 표현은 선행 0 없는 십진 문자열이며 묵시적 정수 변환을 제공하지 않는다.

| 타입 | 의미와 범위 |
|---|---|
| TimestampMs | Unix 밀리초, 0–2^63−1 |
| Sequence | 사건 순서, 0–2^64−1 |
| Version | 상태·레지스트리 버전, 0–2^32−1. 레지스트리 등록은 양수 요구 |
| Quantity | 수량, 0–2^32−1 |
| Generation | 발행·실행 세대, 0–2^64−1 |
| AdmissionEpoch | 검표 폐기 epoch, 0–2^64−1 |
| DurationSeconds | 기간의 초 단위, 0–2^32−1 |
| BasisPoints | 비율, 0–10,000 |

기존 Core의 시험용 초 단위 시각을 밀리초로 자동 변환하지 않는다. 기존 `contracts.INTEGER_FIELDS`도 기존 reference profile에 한정한다. 새 실행 저장소는 각 필드의 단위와 타입을 명시적으로 선택해야 한다.

## 기존 KRW 실행기로 들어가는 제한된 경계

`LegacyKRWAdapter`는 기본적으로 비활성이다. 운영 코드가 명시적으로 선택한 설정과 `enabled=True`가 있어야 변환한다. 다음 조건을 모두 만족한 하나의 금액 필드만 원래 Core용 정수로 내보낸다.

1. 입력은 올바른 `AssetAmount`이고 어댑터에 고정된 레지스트리 문맥과 같다.
2. 자산은 정확히 기존 KRW 명세다. namespace·reference·정밀도·자산 한도가 모두 일치해야 한다.
3. 금액은 기존 Core의 필드별 `10^12` 한도 안이다. 새 자산 모형이 u128을 표현한다고 기존 실행기가 그 전 범위를 지원하는 것은 아니다.

USDC 최소단위 `1000000`을 KRW `1000000`으로 변환하거나, 통화 표시 문자열만 KRW로 바꾸는 경로를 허용하지 않는다. 어댑터에는 외부 호출·서명·dispatcher·관측 생성 기능이 없다. 변환 후에도 기존 Core의 actor/source/의무 검사가 적용된다. 기존 Core를 곧바로 외부 HTTP 요청에 노출할 수 있는 인증 계층은 아니다.

## 검증과 다음 개발

직접 실행한 시험과 소스 해시는 `validation/2026-09-14-foundation/`에 보존한다. Python 두 환경의 전체 회귀와 언어 간 고정 시험값을 확인한다. 전체 CI에서는 기존 공개·유상·비공개 Sui 여정 및 ZK 조작 거절 검사도 유지한다. 새 커밋의 완료 여부는 해당 커밋의 CI로 판정한다.

S07은 이 기반 위에서 상위 Order와 복수 QuoteSnapshot, 외부 Observation, Allocation, IssuanceOutcome, Obligation, RefundReservation, ExecutionIntent와 자산별 Journal을 연결한다. 한 Quote가 한 회차·자산만 계산하는 제한을 Order 전체에 옮기지 않는다. 승인된 자산·정책 버전은 주문 생성의 선행조건이다. 중복 관측, 동시 환불 예약, 예약 직후 종료, 늦은 성공·일부 발행 실패를 실제 영속 경계에서 검사한다.

과거 저장 유실의 원인, HOLD 감사 기록의 원격 보존, 실제 PG 인증, 다중 작업자의 실행 권한, 거래 단위 체인 취소, 체인 규모와 비공개 전체 생애주기는 후속 영역으로 남는다. S05 복원은 조회·대사 전용이며 G0 전체 완료를 선언하지 않는다.
