# KIX 프로토콜 통합 코어 v0.1

2026-09-11. 티켓의 구매·공식 재판매·입장·환불·관계자 정산을 연결하는 **실행 가능한 참조 명세**다. 합성 데이터만 사용한다.

## 실행

검증 환경: Python 3.12.14, SQLite 3.53.1, cryptography 46.0.0. `core.py` 자체는 표준 라이브러리만 사용한다. 과거 권리 모형과의 연결 검사에 cryptography가 필요하다.

```bash
python3 -m pip install -r requirements.txt
python3 verify.py
```

실행 결과는 `results/verification.json`, `results/tests.txt`, `results/synthetic_lifecycle_trace.json`에 저장된다. 31개 테스트에는 결제·지급 증거 도착 순서 2개와 별도 SQLite 연결 2개의 좌석 경합이 포함된다. 이는 31개 독립 실서비스 시험이나 보안·합의 증명이 아니다.

## 현재 구현의 정확한 범위

이 버전은 **통합 코어 계열의 첫 버전**이다. 기존 예매 폭주 v0.7, 운영자 독립 권리 v0.1, 환불 검증기 v1.6 등의 개별 연구 계열을 보존한다. GitHub 연결에서 확인된 저장소는 `soulbounddao-ADMIN/soulbound`였으며 KIX 저장소는 보이지 않았다. 기존 자료에서 코드를 가져와 신규 결과물로 구성했다.

운영용 서버가 아니다. 원장의 권한 있는 주체를 나타내는 actor 문자열과 PG 입력은 모두 시험 가정이다. 모든 핵심 상태를 SQLite의 한 상태 행에 직렬화하며 실제 체인 거래를 보내지 않는다. 이는 운영자 독립성이나 블록체인의 성능을 입증하는 구현이 아니다. 두 기존 모형과는 계약 호환성을 검사했으며 세 모형이 분산된 실서비스로 연결됐다는 뜻이 아니다.

합성 환불 정책은 `FULL_CHAIN_UNWIND_FIXTURE`다. 모든 거래를 원결제·원구매자별로 환원한다. 수수료 전액 환원, 실제 PG 비용 0원, 거래별 자금 격리, 공연 종료 후 배분금 지급을 가정했다. 이를 KIX의 확정 약관이나 실제 PG 계약이라고 사용하면 안 된다. 다른 환불 구조는 별도 정책 버전과 검증 사례로 추가한다.

실제 PG 송신, Sui/Move 구현, 외부 서명 인증, ZK, 키 복구, 오프라인 게이트 내구성, 무인 장애 복구, 실제 대출·투자, 광고 발송은 이 패키지의 구현 범위에 없다.

출원·대외 공유·유료 서비스 실행은 수행하지 않았다. 개발 검증 결과로 특허 신규성·진보성이나 실시 자유를 새로 판단하지 않는다.
