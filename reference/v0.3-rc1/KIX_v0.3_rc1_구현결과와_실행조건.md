# KIX v0.3-rc1 구현 결과와 실행 조건

**v0.2를 기반으로 금융·생애주기 반례를 수정하고, Sui 권리 프로그램·독립 클라이언트·최소 현재성 회로를 작성했다. 다만 실제 Sui·ZK 실행은 아직 완료하지 못했다. 따라서 정식 v0.3 완료본이 아니라 검토 가능한 개발 후보(rc1)다.**

작성일: 2026-09-11.

## 실제 확인한 범위

| 항목 | 결과 |
|---|---|
| 원래 v0.2 배포 파일 | 42개 해시가 그대로 유지됨 |
| 첨부 독립 호출 코드 | 9개 관찰 R01–R09 재현 |
| Python 회귀 검사 | 기존 72개 + 신규 16개 = 88개 통과 |
| 기존 선택 방어 변이 | 14개 모두 탐지; 전체 변이 커버리지 의미는 아님 |
| 백업/직렬화 오프라인 검사 | Node 내장 런타임 검사 4개 통과 |
| 주요 합성 결과 JSON | 동일 환경 재실행 시 2개 바이트 일치 |
| JavaScript 클라이언트 | 구문 검사 수행; SDK를 불러와 실행한 것은 아님 |
| Move 컴파일/Move 검사 | 미실행 |
| 실제 Sui 로컬넷 여정 | 미실행 |
| 회로 컴파일·증명 생성·Sui Groth16 검증 | 미실행 |
| 실제 PG/은행 호출·실제 자금 이동 | 없음 |

이 환경에는 `sui`, `cargo`, `rustc`, Sui SDK와 증명 도구가 설치되어 있지 않았다. 공식 설치 파일에 대한 셸 네트워크 요청은 응답을 받지 못했고, 후속 패키지 배포처 요청은 **“network approval was cancelled before a decision was returned”**로 종료됐다. 승인 검토가 위험하다고 판정했다는 이유까지 제공된 것은 아니다. 접근 제한을 우회하지 않았으며, 없는 실행 영수증·증명·컴파일 결과를 만들지 않았다.

원본이 재현하던 대표 결과는 다음처럼 바뀌었다.

- 정산 100,000원이 정상 반영된 뒤 **미반영 정산액 0원**.
- 고객 환불 확인과 실패 표식이 상충하면 **추가 현금 환불 준비 거절**.
- 95,000원 중 40,000원 지급의 최종 종료 후 **미실행 55,000원 해제**, 공연 취소 회수 대상 **40,000원**. 지급분 40,000원 반환을 반영하면 해당 회수 잔액 **0원**.
- 충돌 원문을 하나 보존하면 **충돌 수 1건**, 증거 digest 변경.
- `a` + `b/c`, `a/b` + `c`는 **서로 다른 재고 2개**.

`results/review_trace_v03.json`에는 이 수정 후 실제 합성 실행 결과를 넣었다. 합성 원천의 진술이 현실에서도 참임을 증명한 자료는 아니다.

## 2. 금융·송신 계약에서 명시한 한계

`raw_inbox.APPLIED`는 입력이 도메인에서 처리됐다는 뜻이다. 상충을 보존한 경우에도 APPLIED가 될 수 있으며 그때 결과의 `financialApplication=false`가 실제 분개를 하지 않았음을 표시한다. 경제적 사실의 `OPEN/RESOLVED/CONFLICT`, 해당 변형의 원장 반영 operation/sequence를 별도로 보존한다.

상충을 `CONFLICT`로 남긴 뒤 운영자가 마음대로 해제하는 명령은 추가하지 않았다. 상충의 진위를 판단할 원천 조회·대사 계약과 관리 검토 절차는 후속 작업이다. 이미 대체 지급이 실제로 실행된 뒤 늦게 긍정 증거가 왔다면 과거 지급을 소급해 없앨 수 없다. 그 경우에도 증거와 부담을 남기고 추가 실행을 차단하는 방향이다.

`send_effect`는 송신 의도만 기록하고 네트워크 요청 바이트를 응답으로 내주지 않는다. `claim_effect`와 `dispatch_effect`가 인수와 실행 권한을 구분한다. 작업자 lease는 이미 외부에 전달된 요청을 취소하는 기능이 아니다. 취소 이전에 발급한 요청이 늦게 처리될 가능성은 원천 결과와 대사로 다뤄야 한다.

`NOT_FOUND_REPLAY_SAFE`, 키 유효시간 1시간, 조회 유효시간 30초, 부분 종료의 원천 cursor는 **합성 어댑터 계약**이다. 실제 PG의 존재하는 API·보장이라고 주장하지 않는다. 실제 연동에서는 제공자의 계약을 확인하고 이 조건을 충족하는 조회와 동일 요청 재제출만 허용해야 한다.

증거 digest 범위는 `GLOBAL_INBOX_AND_LEDGER_V1`로 표시한다. 행사별 금액과 전체 범위 미귀속·미처리 건수를 혼동하지 않도록 이름/범위 필드를 추가했다. 전체 PG 자료가 빠짐없이 수집됐다는 완전성 보증은 여전히 `false`다.

## 3. 이번에 추가한 체인·독립 클라이언트 소스

`rights.move`에는 공개 발행·보유자 제안·수신자 수락·결제 증거 소모·리셀 배분 근거·보유자 검표 승인·다른 검표자의 1회 소비·환불 요청·폐기·재고 재발행 조건을 작성했다. KIX의 단일 `operator`가 모든 이전을 확정하는 조건은 넣지 않았다.

`independent.mjs`에는 직접 서명, 서명 바이트 선저장, 성공/실패 분리, 직접 RPC 조회, 암호화 백업·복구를 작성했다. 읽은 객체는 BCS로 해석하고, 실제 공유 상태의 전이 조건을 Move에서 다시 검사하도록 했다. RPC 응답 자체의 검증자 서명 확인은 아직 없다. Sui SDK에서도 실행 결과와 실행 성공을 구분한다. [공식 실행 API](https://sdk.mystenlabs.com/sui/clients/executing)

`localnet.mjs`는 실제 로컬넷에서 다음을 검사하기 위한 스크립트다.

> A에게 발행 → A가 B에게 이전 제안 → B가 수락 → B가 백업 → 설정 프로세스 종료 → 새 프로세스의 B 복구 → 다른 검표자의 사용 → A의 옛 권한과 재사용 거절.

로그인·salt·KIX 저장소·대납 API를 호출하지 않는 제한 프로파일이다. 실제 운영 중인 KIX 서비스를 전부 종료한 현장 시험은 아니다. 아직 로컬넷 실행도 하지 못했으므로 운영자 독립성의 입증으로 보고할 수 없다.

## 4. 비공개 현재성 소스와 제한

최소 회로를 기존 Python 비공개 모형 테스트에 덧붙이는 방식으로 만들지 않았다. 후보 Move 프로그램의 같은 `Ticket`을 `SHIELDED`로 바꾸고, 해당 공연의 노트·현재 세대·소비 집합을 검증하도록 연결했다.

- 노트 생성 회로: 정확한 slot·generation의 commitment 생성 증명.
- 소비 회로: 발행 노트 포함 + 동일 slot의 현재 세대 + 공통 nullifier + 검표자/요청/만료 문맥.
- Move 검증: 현재 두 루트와 소비 집합을 읽고, 공연에 고정된 불변 Verifier만 사용.
- 사용자 복구: 노트 secret과 지갑 키를 암호화해 보관. 공개 체인 자료와 로컬 proving 자료로 경로와 증명을 다시 만들도록 구성.

Sui Groth16은 앱이 예상 검증키를 고정/확인해야 한다. 이번 후보는 공개 입력 4개/6개를 사용하지만, 실제 회로 생성·직렬화·Sui 수락은 확인하지 못했다. [공식 Groth16 문서](https://docs.sui.io/develop/cryptography/groth16)

**비공개 리셀·환불·재발행·키 교체까지 구현했다는 뜻은 아니다.** 비공개 전환 뒤에는 검표와 권한 있는 폐기/공연 취소만 허용한다. 공개 경로로 돌아가 같은 좌석을 다시 팔 수 없다. 최대 16개 슬롯의 제한 모형이며, 공개 shield 기록과 시간·주소 연결 가능성이 남는다. 작은 집합에서 익명성이 보장된다고 주장하지 않는다.

상세 입력·권한·노출 범위·기존 방식 비교는 `DESIGN_SUI_ZK.md`에 적었다. accumulator/익명 자격증명에 대한 체계적 조사와 특허성 평가는 아직 완료하지 않았다.

## 5. 다음 작업을 막는 조건과 재개 지점

필요한 것은 **공식 Sui 도구와 npm 의존성을 설치할 수 있는 실행 환경**이다. 이 조건이 풀리면 다음 순서로 계속해야 한다.

1. 실제 CLI·SDK 버전과 lock 파일을 고정하고 Move 컴파일 오류 및 SDK 응답 형식 차이를 수정.
2. 공개 권리 여정을 실제 로컬넷에서 실행하고 트랜잭션 digest/효과/실패 근거 보존.
3. 회로 생성과 로컬 proof 검증 후 Sui Groth16 호환성 검증. 잘못된 키·과거 세대·잘못된 문맥·재사용의 거절 확인.
4. 서로 다른 RPC/운영 경로와 복구 자료·가스·검표 권한을 바꿔 장애 독립성 시험.
5. 유상 리셀·환불·배분과 Python/실제 PG 브리지를 동일 권리에 연결.

현재 수정본을 검토하거나 재개하는 명령과 파일 위치는 패키지 `README.md`에 있다. **이번 결과로 Sui 이전 완료나 실제 프라이버시·운영자 독립성 구현 완료를 선언하지 않는다.**
