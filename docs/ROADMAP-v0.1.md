# KIX 후속 개발 계획

작성일: 2026-09-11. 아래 항목은 **미구현 계획**이다. 기준 구현의 31개 검사 통과와 혼동하지 않는다.

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 취소 후 미송신 지급 차단, 환불 노출액 표시, 생존 변이의 회귀 검사 | 취소 확정 뒤 새 지급 송신 차단. 기존 핵심 방어를 제거하면 검사 실패 |
| 2 | 원결제 취소·정산 조정·계좌 송금별 실행 프로필, 순정산·수수료 | 필요한 원천 증거·분개·완료 상태를 프로필별로 대조 |
| 3 | 재고/관람권 분리, 반환 좌석 재발행, 무상 양도·초대권, 게시/예약 구분 | 구권리의 부활 없이 신권리 발행. 입장·이전·환불 충돌 방지 |
| 4 | 원자료 inbox, 실행 시도별 outbox, PG ID 규격 매핑 | 미귀속·상충 관찰 보존. 중복 사실의 중복 반영 차단 |
| 5 | 체인 권리 프로그램과 확정 영수증 | 별도 원장의 권리 전이·조회 복구·취소 경합 검증 |
| 6 | 운영자 독립 검증·복구 및 ZK 프로필 | 정해진 장애 조건에서 권리 복구. 비공개 입력과 검증 명제의 실제 구현 |
| 7 | 금융 자료와 마케팅 동의 연결 | 증거 범위·기준 시점·미확정 부담 표시, 발송 허가 시 동의 확인 |

Sui는 구체 구현 후보로 유지한다. 체인·PG 연결을 같은 SQLite 트랜잭션으로 처리했다고 가정하지 않는다. 처음에는 권리 모듈 설계를 병행할 수 있지만 아직 수정 중인 금융 프로필을 확정된 운영 규칙으로 배포하지 않는다.

대표 검증 여정: 승인 물량 발행 → A 구매 → B 리셀 → B의 권리 수신·검증 → 입장 또는 환불 → 배분·수수료·회수 부담 대조. 무상 양도와 반환 좌석 신권리 발행은 별도 분기로 확인한다.

전체 상세 근거는 [v0.1 검토보고서](../reviews/v0.1-2026-09-11/KIX_통합프로토콜_v0.1_상세검토.md)에 있다. 이 계획은 특허 등록 가능성 판단이나 실서비스 출시 승인에 해당하지 않는다.
