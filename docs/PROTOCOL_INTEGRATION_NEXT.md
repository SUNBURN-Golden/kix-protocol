# 권리·거래·정산 통합의 다음 구현 계약

2026-09-13. 이 문서는 다음 개발의 완료 기준이며, 아래 연결이 구현됐다는 보고가 아니다.

## 제품 경계

KIX는 예매·공식 리셀·검표·금융·마케팅 서비스가 공통으로 사용하는 권리·거래·정산 프로토콜이다. 소비자용 화면이나 Vercel Import 성공을 프로토콜 완료 조건으로 삼지 않는다.

현재 Python Core는 SQLite를 권위로 삼는 합성 모형이고, Sui는 별도 권리 구현이다. `dispatch.py`와 `adapters.py`는 외부 PG/은행 통신을 하지 않는다. 현재 공개 여정은 금액 0인 선물 이전이다. 이 사실들을 유상 거래·지급 통합 완료로 해석하지 않는다.

## 첫 통합 범위

한 공연, 소수 좌석, 최초 구매와 공식 유상 리셀 1회, 기존에 정한 배분 정책, 취소·환불 및 지급 결과 대사까지 연결한다. ZK 설정·현재성 보완은 이 통합과 별도 완료 항목이다. 비공개 리셀·환불·재발행은 아직 허용하지 않는다.

실제 Sui 로컬넷과 장애를 제어할 수 있는 모의 PG/은행 어댑터를 먼저 연결한다. 모의 제공자와 실제 PG 테스트 환경의 증거를 명시적으로 구분한다. 모의 결과를 실제 결제나 은행 지급 사실로 승격하지 않는다.

## 반드시 보존할 불변 조건

1. 거래는 네트워크·계약·공연·권리 식별자·권리 버전·판매자·구매자·통화·금액·정책 버전 또는 정책 해시에 결합된다. 같은 PG 참조를 다른 거래에 재사용할 수 없다.
2. 같은 요청 ID와 같은 본문은 같은 의미의 결과로 귀결된다. 같은 ID에 다른 본문이 오면 거절한다. 응답 유실이 결제·이전·지급을 중복 실행시키지 않는다.
3. 결제 확인, PG 매입/정산, 실제 가용 자금은 별도 사실이다. 체인 이전 성공도 송금 완료를 뜻하지 않는다.
4. 권리 이전이 불명확하면 성공이나 확정 실패로 단정하지 않는다. 원 거래 digest를 조회하고, 허용되는 경우 같은 서명 바이트를 재제출한다. 복구 중 새 소유권 이전을 임의로 생성하지 않는다.
5. 결제가 처리됐지만 권리 이전이 확정 실패한 경우, 권리 유효성과 후속 거래를 확인한 보상 절차를 기록한다. 시간 초과 하나만으로 환불과 재판매를 동시에 허용하지 않는다.
6. 배분 총액은 해당 정책의 거래 금액과 일치한다. PG 비용·반올림 잔액·환불 부담 주체가 정해져야 하며, 지급 완료와 지급 예정액을 구분한다.
7. 지급 또는 환불 상태가 불명확한 동안 관련 자금과 의무를 이중 사용하지 않는다. 늦은 성공, 부분 지급, 사후 반환은 원 의무에 연결해 재계산한다.
8. 폐기·입장·취소·이전이 경합해도 정책이 허용한 단일 결과만 유효하다. 외부에서 제출한 역할 문자열을 인증 근거로 쓰지 않는다.

## 어댑터의 최소 계약

| 경계 | 입력/출력에서 필요한 것 |
|---|---|
| 거래 명령 | 거래/작업 ID, 인증된 주체와 권한 범위, 예상 권리 버전, 고정 정책, 정규화한 본문 해시 |
| PG/은행 요청 | 제공자·환경·가맹점 범위, 원 결제/지급 식별자, 멱등 키, 요청 바이트, 유효한 재시도 조건 |
| PG/은행 관측 | 원자료 해시, 검증된 출처, 제공자 거래 ID, 관측 시점, 상태/자금 사실의 구분 |
| Sui 제출/관측 | 체인·패키지·공연·객체 ID, 정확한 제출 digest, 실행 상태, 관련 이벤트·객체 버전 |
| 복구 | 저장된 원 요청과 관측 이력, 충돌·불명확 상태, 조회/동일 요청 재시도/보상 결정 근거 |
| 금융 조회 | 기준 시점, 미정산채권·실제 가용자금·환불 부담·지급 진행 중 금액·상충 증거의 구분 |
| 마케팅 조회 | 정보 항목별 허용 범위, 동의 버전·철회·발송 직전 재확인 조건 |

필드 이름과 전송 형식은 구현 시 확정한다. 기존 Python 명령과 Sui `Terms`/`PaymentEvidence`의 의미 차이를 먼저 매핑하고, 이름만 맞춘 어댑터를 만들지 않는다.

## 완료를 입증할 여정

| 사례 | 필요한 결과 |
|---|---|
| 구매·발행·유상 리셀·배분·정산 | 동일 거래 근거로 권리 상태와 금전 의무가 일치함 |
| 결제 응답 유실·동일 웹훅 중복 | 중복 발행·배분이 발생하지 않고 조회로 복구됨 |
| 결제 성공 뒤 체인 제출 실패 | 모호한 상태와 확정 실패를 구분하고 적절한 복구/보상으로 귀결됨 |
| 체인 성공 뒤 응답 유실 | 원 digest로 성공을 확인하고 이전을 재실행하지 않음 |
| 리셀·입장·취소의 경합 | 상호 배타적인 권리 결과와 대응 금전 의무가 보존됨 |
| 지급 응답 유실 뒤 늦은 성공 | 새 지급으로 중복 처리하지 않음 |
| 부분 지급·부분 환불·사후 반환 | 실제 확인한 금액만 장부에 반영되고 미해결 잔액이 남음 |
| 다른 체인/권리/금액/정책의 증거 | 결합 불일치로 거절됨 |
| 재시작 후 복구 | 영속 기록만으로 같은 상태를 복원하고 미해결 작업을 이어감 |

실행 결과에는 사용한 모의/실제 어댑터, 소스 커밋, 입력·관측 근거, 체인 결과, 최종 장부와 남은 불명확 상태를 포함한다. 기존 합성 검사 개수만으로 이 통합의 완료를 선언하지 않는다.
