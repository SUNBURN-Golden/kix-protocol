# Local Commerce resale read decision

The KIX maintainer approved six Protocol-owned reads on 2026-11-24 at 10:07 KST under JunTae's standing order. The approval covers `FIXTURE_ONLY` data in the in-memory loopback integration gate. `read-model-reference` retains ownership of canonical wire names, error names, and catalogue insertion. The 84 command catalogue and both historical SDK compatibility tuples keep their original scope. ## Visibility and ordering

| Query | Fixture visibility |
| --- | --- |
| `list_open_listings` | Any valid fixture actor sees summaries of attached, unexpired `LISTED` rows. The summary is `listing_id`, `show_id`, `amount`, `currency`, `expires_ms`, `expired`, and `phase`. |
| `get_listing` | The seller and, after transfer, the current holder can see the listing. A designated recipient or buyer hold confers no listing-detail access before transfer. |
| `get_right`, `get_presentation` | The current holder sees the existing point views. Presentation comparison uses the supplied version and holder label, so an authorized comparison can return false. |
| `get_settlement` | Follow the listing's explicit binding when the settlement's `trade_id` equals the `listing_id`. The organizer fixture on that listing's show and the settlement's debtor fixture can read the view. Null and unrelated bindings use the same refusal as an absent listing or unauthorized actor. |
| `get_operation_recovery` | Recovery compares the exact actor label on the accepted write. It grants access only to that attempt's recorded receipt. |

Actor labels have `FIXTURE_ONLY` semantics. Point visibility failure and subject absence both yield HTTP 404 with `NOT_FOUND`. Listing position is the one-based index of its first accepted `list_resale` journal entry, ascending, with `listing_id` ascending as the tie-breaker. Pages default to 20 entries, accept 1–100, and expose `entries`, `next_cursor`, and `truncated`. Pass back the exact cursor, actor, and page size. The cursor binds the query, actor, page size, ordering and snapshot. An accepted resale entry or a new gate generation ends the cursor's lifetime. Reads and exact write replays leave the cursor usable. No wall-clock TTL or listing history policy is implied.

## Freshness and recovery

`accepted_through` contains the source (`resale` or `settlement`), process `generation`, and `journal_entries`; it includes `logical_time_ms` for resale. Its `token` binds those fields to the gate instance. Generation and token signing use ephemeral in-process randomness. A caller can omit `minimum_watermark` for a current observation or pass an earlier `accepted_through` verbatim as a lower bound. A watermark from another source or generation, a mutated token, or a cut ahead of the local source yields `READ_WATERMARK_UNMET` (422). Cursor failure yields `READ_CURSOR_REFUSED` (422). These error labels apply only to this transport. The read envelope carries schema version `0.1`, mode `REFERENCE_IN_MEMORY`, and a SHA-256 `query_digest` over compact, sorted UTF-8 JSON for `{"query": operationId, "input": request}`. The reserved `ReadObservationV1` fields are outside this envelope.

Recovery accepts exactly one of `operation_id` (local-call `operationId`) or `trace_id` (write `X-Request-Id`). The typed `subject` contains the existing write `action`, its catalogue `field`, and the subject `id`. Pass an observed source watermark in `through`. The worker records a copy of the accepted `resale_*` or `settlement_*` receipt before HTTP reply. Its accepted position must be covered by the cut in the same source and generation. An exact write replay cannot attach a later operation or trace identity to the first acceptance. Reuse of either identifier with a different write fingerprint fences that identifier. The fingerprint binds the operation ID, actor, action and body.

An in-memory write deadline returns `CORE_BUSY` (503) and fences further writes and `/ready` for the rest of the process. The same worker can finish the pending job and then serve a fresh cut and recovery reads. A read that reaches its own deadline returns `CORE_BUSY`. Outstanding read jobs retain their worker slots up to the configured in-flight limit. Worker failure, drain and journal divergence prevent reads. Restart discards the process-local receipt and cuts.

The fixture retains up to 128 first receipts of up to 65,536 bytes each, with oldest-first eviction. It tracks up to 2,048 identity entries across both identifier types. Identity slots survive receipt eviction for the rest of the process so an evicted identity cannot be reused to recover a later receipt. Once the index fills, new identities receive no recovery evidence. These are local memory bounds. Missing, ambiguous, evicted, mismatched or insufficient evidence yields HTTP 200 `{"status":"UNKNOWN","retry_granted":false}` without a receipt. Acceptance gives a read envelope carrying the requested cut and the first receipt. Neither result grants a retry. The reads execute zero commands and work without a readiness directory or browser CORS. Recovery is process-local and has no durable or cross-process authority.
