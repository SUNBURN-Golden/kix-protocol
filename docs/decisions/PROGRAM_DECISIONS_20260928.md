## 1. 결정 원칙

1. **범위는 넓게 연다.** 권리·발행·예매·매표·리셀·검표·정산·여신·마케팅·AI 위임·데이터를 한 프로그램으로 계속 진행한다. 제품 표면을 줄이지 않는다([개발계획 §1](../DEVELOPMENT_PLAN.md)의 "삭제하지 않는다" 원칙 유지).
2. **되돌리기 어려운 것만 잠근다.** 잠금 대상은 실자금, 실제 제공자 호출, 공개 운영 엔드포인트, 체인 mainnet 실행, 커널 잠금 blob, 자체 복제·합의다. 잠금은 영구 금지가 아니다. 증거가 모이면 여는 문이며, 각 잠금의 해제 조건을 §5에 적는다.
3. **만든 자산은 버리지 않는다.** 병합분은 되돌리지 않고 후속 단계의 기반과 시험 자산으로 쓴다.
4. **절차는 가볍되 추적 가능하게 한다.** 착수는 게이트 기록 한 줄로 한다. 병합은 사람이 하고, exact-head CI 조건은 유지한다.

### 2.1 Track P 승인 범위

- 계약 문서(`docs/contracts/`)의 신규 작성과 개정. 초안 버전을 표기한다.
- `reference/` 아래 in-memory 참조 모델, 상태기계, mock·시뮬레이션
- Move `rights`·`zk_gate` 확장과 localnet 시험. 새 coin/TIX 모듈은 제외한다(Task 005 결정 5).
- 계약 전용 OpenAPI 개정. 새 명령을 카탈로그에 올리는 것도 포함하되, 계약 문서와 pin 검사를 함께 갱신한다.
- loopback 비운영 통합 관문과 readiness 래퍼(§4)
- **비운영 0.x client SDK·schema 산출물.** 계약 전용 OpenAPI에서 파생하며, 분리 앱 저장소가 소비한다. 안정 1.0, 공개 배포, KTX→KIX 일괄 치환은 Track K 3단계 재승인 대상으로 남긴다.

- **AI 위임 권한 계약과 mock.** 조회·제안·실행 권한, scope, 금액, 기간, 회수 조건을 다룬다(개발계획 §14). 모델 출력만으로 발행하거나 지급하지 않는다.
- F04 여신은 mock·시뮬레이션만 한다(Task 005 결정 6).

## 4. D-3 결정안 — readiness 저널 허용 (경계 안에서)

선택지 1(허용)을 택한다. `readiness/`는 **비운영 로컬 준비 래퍼**다. AGENTS.md §5의 "storage-engine or log-engine implementation"에 해당하지 않는 것으로 분류한다.

**경계.** 이 선을 넘으면 R2·자체 저장 엔진 금지 영역이다.
- 단일 프로세스, 단일 작성자, 로컬 파일로 한정한다. 기본은 비활성이며 `--readiness-dir`를 줄 때만 켠다.
- `protocolTruth`·`productionConformance`·`productionReadiness`·`productionEndpoint`는 `false`를 유지하고, FSM `durable`도 `false`로 둔다.
- 복제, 합의, 다중 작성자, 네트워크 전송, 원격 저장, 운영 기본 활성은 금지한다.
- 저널을 정본 원장, 감사 증거, 외부 exactly-once 근거로 쓰지 않는다.

**경계 안에서 허용되는 확장.**
- fault 시나리오 추가
- 명시적 schema 버전 이전 함수 추가. 추측 이전은 금지다.
- 새 FSM 래핑
- 관측과 감사 줄 개선
- 예산·과부하 정책 개선

**가능성 보존.**
- fault suite(찢긴 쓰기, 내구 전 크래시, 재생 멱등, 예산 거절, 동시 보유)를 Track K 4·5단계 backend 후보의 공통 적합성 시험으로 재사용한다.
- 기성 backend를 채택하면 이 래퍼는 같은 인터페이스 뒤에서 교체할 수 있는 구조를 유지한다.
