# ZK 설정과 권리 현재성 보완

기준: `2658a43aefa792ff783457188814f8598a62f5b0`. 검증일: 2026-09-13.

## 문제와 수정

기존 `setup-zk.mjs`는 Powers of Tau 기여 뒤 `groth16 setup`으로 만든 초기 키를 바로 사용했다. mint/spend 각각의 `zkey contribute`가 없었다. 저장된 공개 증명과 검증키만으로 소비 표식 또는 회로가 금지한 action 값을 바꾸고 증명 C항을 함께 조정하면 검증을 통과했다. 입력만 바꾸는 기존 음성 검사로는 이 결함을 탐지하지 못한다.

수정은 다음과 같다.

- 두 회로 각각에 별도 기여와 `zkey verify`를 수행하고 그 결과에서 검증키를 내보낸다.
- 설정 시작 시 과거 manifest를 제거한다. 완성된 기여 키·검증키·바이너리·회로·WASM의 해시를 새 manifest로 기록한다.
- 클라이언트는 과거 manifest, 초기 키의 gamma=delta 패턴, 필수 파일 해시 누락, JSON 검증키와 바이너리의 불일치를 거절한다. 직접 증명 생성 함수를 호출해도 파일 검사를 수행한다.
- 기존 결함 재현과 새 키의 조작 거절을 회귀 검사로 보존한다.
- 별도 실제 로컬넷 공연에서 폐기·루트 변경·정상 권리의 증명 재생성·공연 취소를 검사한다.
- CI는 키 생성·ZK 회귀·비공개 로컬넷을 기본 실행한다. 설정만으로 GitHub 실행 성공을 주장하지 않으며 PR 실행 상태는 별도로 확인한다.

키 검사와 manifest는 운영용 신뢰 설정을 인증하지 않는다. 여전히 한 주체가 만든 시험용 키이며 회로 감사·다자 설정·운영 키 관리가 완료된 것이 아니다.

## 기존 키 교체

과거 자료는 결함 재현 근거로 남기며 정상 운영용 파일로 재사용하지 않는다. 새 키는 새로운 immutable Verifier 객체와 그 객체 ID를 고정한 새 Show에서 사용한다. 기존 Show의 검증키를 자동 교체하는 기능이나 기존 권리를 이관하는 기능은 추가하지 않았다.

## 남은 범위

검증자 1개, 신뢰하는 RPC, 16슬롯, 공개되는 전환 거래·주소, 비공개 리셀·환불·unshield·키 교체·재발행 미구현이라는 한계는 유지된다. 현재 설계는 다른 노트의 추가·폐기로 루트가 바뀌면 멀쩡한 노트도 증명 갱신이 필요하므로 동시 검표·재시도 정책을 더 검토해야 한다.

Python 금융 모형과 실제 Sui 유상 거래·PG·은행 사이의 통합은 이번 수정으로 구현하지 않았다. 다음 개발은 [프로토콜 통합 계약](PROTOCOL_INTEGRATION_NEXT.md)의 원 거래 식별, 실패·복구, 배분·정산 대사를 따른다. 웹 화면이나 Vercel 배포는 이 단계의 완료 조건이 아니다.
